# Adaptive AFO Care Dashboard and Backend: Design

Date: 2026-11-07. Project: BioHacks McMaster 2026, patient Alex Chen (47, ALS). See `docs/plan/PATIENT_CASE.md`. This replaces the earlier backpack-focused dashboard design.

## Intent

Alex has right foot drop and two falls in three months, both after 6 PM, on the stairs or at dusk. The device is an adaptive ankle-foot orthosis (AFO) on his right leg: it senses ankle angle, toe clearance and gait events, detects stair climbing, and raises its lift assist as fatigue lowers his toe clearance. A Raspberry Pi reads the sensors and sends data to the backend. This dashboard is how his family and his physician see that data: stability metrics, Gemini-generated physiotherapy recommendations, and insights into how the disease is progressing between his three-monthly ALS clinic visits.

## Goals

- One Next.js app with two modes, switched by a segmented control in the header: Family and Physician.
- Ingest AFO data from the Raspberry Pi into Tiger Data (TimescaleDB).
- Show stability metrics: ankle angle, toe clearance, gait events and cadence, stair ascent and descent, assist level, a composite stability score.
- Gemini integration: a plain weekly summary for family, and a structured report for the physician with stability findings, progression vs baseline, suggested physio focus, and questions for the next visit.
- Progression insights: stability score trend, foot drop severity trend (dorsiflexion, clearance, assist needed over months), clinic scores (ALSFRS-R, 10 m walk) entered manually and plotted next to sensor data.
- Live view in Physician mode.
- An AFO simulator posing as the Pi, plus seeded history, so everything demos without hardware.
- Look and feel follows the apple-design skill (emilkowalski/skills, `skills/apple-design/SKILL.md`).

## Non-goals

- Login or auth. Demo only.
- Mobile or projector layouts. Laptop only (1280 to 1920 px); narrower widths must not break.
- Push notifications, SMS, email.
- Multi-patient list (schema keeps `patient_id`).
- Pi firmware and AFO mechanics (they only need the API contract).
- Model training.

## Anti-goals

- Family mode that feels clinical or alarming. Red or orange only for an actual near-trip or fall on stairs.
- Gemini output presented as diagnosis or as a prescription. Physio recommendations are suggestions for his physiotherapist (Daniela Ferreira) to review, with a visible disclaimer.
- Overstating evidence: adaptive AFO assist is a prototype, not a proven ALS treatment.

## Decisions made with the user

- Device: adaptive AFO for foot drop, focused on preventing stair falls. Data comes from a Raspberry Pi.
- Audience: family members and physician. One app, two modes.
- Sensors shown: ankle angle, toe clearance, gait events and stairs, assist level.
- Adaptation: assist rises automatically with fatigue (when clearance drops).
- Physio recommendations: generated by Gemini from the data, framed as suggestions for the physio.
- Progression: stability score trend, foot drop severity, clinic scores.
- Live view: yes, Physician mode. Family sees status only.
- Gemini for family: plain weekly summary. For physician: one report with findings, progression, physio recs, visit questions.
- Stack Next.js + Tailwind. Theme follows system (light and dark). Warm coral accent. Inter. Subtle springs. Laptop only. No auth.
- Stair near-trip in Family mode: in-page banner sheet plus soft chime.
- Credentials: Gemini key available; Tiger Data and Vultr to be set up (steps at the end).
- Delegation: Kiro builds the UI, Codex builds the backend.

## Architecture

Folder `web/` at the repo root, one Next.js (App Router, TypeScript) app.

- `web/server.ts`: custom Node server running Next with a `ws` WebSocketServer at `/ws`. Run with `tsx`.
- `web/lib/types.ts`: shared contract (below). Written first and frozen; both workers import it.
- `web/lib/db.ts`: `pg` Pool from `DATABASE_URL`. `web/lib/bus.ts`: in-process broadcaster from routes to WS clients.
- `web/lib/metrics.ts`: stability score and step-metric helpers.
- `web/lib/gemini.ts`: prompt building and calls.
- `web/db/schema.sql`: tables, hypertables, continuous aggregates, compression.
- `web/scripts/simulate.ts`: AFO simulator posting like the Pi. `web/scripts/seed.ts`: 90 days of history plus clinic visits.
- `web/app/api/...`: route handlers. `web/app/page.tsx` plus `web/components/`, `web/hooks/`: UI.

Ownership: Codex owns `server.ts`, `lib/` (except `lib/types.ts` once frozen), `db/`, `scripts/`, `app/api/`. Kiro owns `app/page.tsx`, `app/layout.tsx`, `app/globals.css`, `components/`, `hooks/`.

## Data contract

```ts
type Terrain = 'level' | 'stairs_up' | 'stairs_down';
type EventType = 'near_trip' | 'fall' | 'assist_increase' | 'assist_decrease' | 'stairs_start' | 'stairs_end' | 'afo_on' | 'afo_off';

interface Sample { time: string; ankleDeg: number; assistPct: number } // ~100 Hz from Pi; ankleDeg + = dorsiflexion
interface Step {
  time: string;           // toe-off
  terrain: Terrain;
  minClearanceMm: number; // toe clearance in swing
  peakDorsiDeg: number;   // peak dorsiflexion in swing
  strideMs: number;
  assistPct: number;      // assist applied this step, 0 to 100
}
interface CareEvent { id: string; time: string; type: EventType; severity: 1 | 2 | 3; message: string; terrain?: Terrain }
interface ClinicScore { id: string; date: string; alsfrsR?: number; walk10mSec?: number; note?: string }
interface DailyMetrics {
  day: string; steps: number; stairSteps: number;
  avgClearanceMm: number; avgPeakDorsiDeg: number; avgAssistPct: number;
  nearTrips: number; falls: number; stabilityScore: number; // 0 to 100
}
interface HourCell { day: string; hour: number; avgClearanceMm: number; nearTrips: number }
interface Report {
  id: string; createdAt: string; audience: 'family' | 'physician';
  rangeStart: string; rangeEnd: string; markdown: string;
}

type WsMessage =
  | { kind: 'sample'; data: Sample }   // throttled to 20 Hz
  | { kind: 'step'; data: Step }
  | { kind: 'event'; data: CareEvent }
  | { kind: 'status'; data: { wearing: boolean; terrain: Terrain; assistPct: number; lastSeen: string } }
  | { kind: 'report'; data: Report };
```

Stability score (0 to 100, my call, tunable in `lib/metrics.ts`): weighted from clearance vs 2 cm target, peak dorsiflexion vs baseline, stride time variability, near-trips per 100 stair steps, and assist needed. Higher is steadier.

## Database (Tiger Data / TimescaleDB)

- `samples(time, patient_id, ankle_deg, assist_pct)`: hypertable, compression after 3 days, retention 30 days.
- `steps(time, patient_id, terrain, min_clearance_mm, peak_dorsi_deg, stride_ms, assist_pct)`: hypertable, compression after 7 days.
- `events(id, time, patient_id, type, severity, message, terrain)`.
- `clinic_scores(id, patient_id, date, alsfrs_r, walk_10m_sec, note)`.
- `reports(id, patient_id, created_at, audience, range_start, range_end, markdown)`.
- Continuous aggregates on `steps`: `steps_1h` and `steps_1d` (counts by terrain, avg clearance, avg dorsiflexion, avg assist, stride variability).
- Anomaly query: hours whose avg clearance falls below the 30-day mean minus 2 standard deviations, plus all stair near-trips. Feeds Gemini.

## API

- `POST /api/ingest` from the Pi, about every 250 ms: `{ samples: Sample[], steps?: Step[], events?: Omit<CareEvent,'id'>[] }`. Inserts and publishes over WS.
- `GET /api/status`.
- `GET /api/steps?from&to`, `GET /api/events?from&to&type`.
- `GET /api/metrics/daily?days=90` returns `DailyMetrics[]`.
- `GET /api/metrics/hourly?days=14` returns `HourCell[]`.
- `GET /api/clinic-scores`, `POST /api/clinic-scores`.
- `GET /api/reports?audience`, `POST /api/reports` `{ audience, from, to }`.
- `WS /ws` pushes `WsMessage`.

## Gemini

- `@google/genai`, current Gemini Flash model, `GEMINI_API_KEY`.
- Input: daily metrics, hourly cells, anomaly hours, stair near-trips, clinic scores, baseline (first 14 days of data). Never raw samples.
- Family report (weekly, auto every Monday 8 AM server time and on demand): short, warm, plain language. Sections: How Alex did this week, Stairs, What to watch for, How you can help (including supporting his home exercises). No numbers beyond a few key ones.
- Physician report (on demand over a chosen range): Stability findings, Progression vs baseline (foot drop severity, assist trend, clinic scores), Suggested physiotherapy focus (for example ankle dorsiflexor work, stair strategy, fatigue pacing, AFO assist tuning), Questions for the next visit.
- System prompt forbids diagnosis, frames recs as suggestions for the treating physiotherapist, notes the AFO is a prototype. UI shows "AI-generated summary, not medical advice" under every report.

## Simulator and seed

- `scripts/simulate.ts`: posts to `/api/ingest` like the Pi. 100 Hz ankle samples shaped like a gait cycle, a step every ~1.1 s, periodic stair bouts, clearance falling through the afternoon and evening with assist rising to compensate, rare near-trips on stairs. Key `n` forces a stair near-trip, `s` toggles a stair bout.
- `scripts/seed.ts`: 90 days of steps and events with slow decline (clearance and dorsiflexion down, assist up, stability score drifting down), worse afternoons and after 6 PM, plus clinic visits about every 3 months with ALSFRS-R and 10 m walk values consistent with the patient case (10 m walk 14.2 s at the latest visit).

## UI

Header: app name, segmented control Family | Physician (spring thumb), connection dot. Mode remembered in `localStorage`.

Family mode (calm reassurance):

- Hero card, one sentence in large type: "Alex is walking steadily today." / "Alex's foot is tiring; the brace is helping more." / "Possible trip on the stairs at 6:20 PM." Plus "Brace on, updated 4 s ago" or "Brace off since 3:40 PM".
- Today strip: 7 AM to 10 PM timeline with soft marks for stair bouts and an orange marker for near-trips.
- Stability this week: one large score with a gentle 7-day sparkline and a one-line plain meaning.
- Weekly summary card: latest Gemini family report.
- Near-trip sheet: slides down from top, plain message and time, "I've checked in" to dismiss, soft Web Audio chime on the same frame.

Physician mode:

- Live: ankle angle trace (last 10 s), last-step clearance vs 2 cm target, current assist %, terrain badge (Level / Stairs up / Stairs down), wearing status.
- Stability metrics: KPI row (stability score, avg clearance, peak dorsiflexion, assist %, stair near-trips per 100 stair steps) with deltas vs previous period; range picker (7, 30, 90 days).
- Progression: 90-day lines for stability score, clearance, dorsiflexion and assist, with clinic visit markers; clinic scores table with an "Add visit" form (ALSFRS-R, 10 m walk, note).
- Time of day: hour-by-day clearance heatmap (14 days) with near-trip dots.
- Events: list with filter chips (near-trip, fall, assist change, stairs).
- Gemini report: Generate for selected range, opens in a side sheet with sections, history list of past reports.
- Two-column grid at 1280 px and up.

Visual system (apple-design skill):

- Inter via `next/font`, size-specific tracking (headings about -0.02em, body 0), tight leading on large type.
- Color tokens on `:root`, light and dark via `prefers-color-scheme`. Neutral grays, warm coral accent (around `#FF6B5B`), semantic orange and red only for near-trips and falls.
- Translucent header (`backdrop-filter`), content scrolls under, scroll-edge fade.
- `motion` library: critically damped springs (bounce 0, about 0.35 s) for sheets, segmented control and live values; press `scale(0.97)` on pointer-down; interruptible. Honor `prefers-reduced-motion` and `prefers-reduced-transparency`.
- Recharts for lines and sparklines; hand-built SVG for heatmap.

## Constraints

- No em dashes in code or text. Comments only for complex edge cases. Concise names.
- Do not commit or push unless the user says so.
- Runs locally with `web/.env`: `DATABASE_URL`, `GEMINI_API_KEY`, `PORT`.
- Deployable to a Vultr VM via the custom server (`npm run build && npm start`).

## Left to the builder

- Component breakdown and hook design.
- Exact stability score weights, chart styling, heatmap color ramp (must work in both themes).
- Simulator signal shapes, as long as the afternoon and after-6-PM decline and stair near-trips are visible.

## Setup the user needs

Tiger Data:

1. Sign up at https://console.cloud.timescale.com and create a service (free tier, region near Toronto).
2. Put the connection string in `web/.env` as `DATABASE_URL`.
3. Run `npm run db:setup` then `npm run seed`.

Vultr:

1. Create a Cloud Compute instance (Ubuntu 24.04, 1 to 2 GB RAM) at https://my.vultr.com; open ports 22 and 3000.
2. SSH in, install Node 22, clone the repo, fill `web/.env`, `npm ci && npm run build`, run `npm start` under `pm2`.
3. Point the Pi and the dashboard at `http://<vm-ip>:3000`.
